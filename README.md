# Спадчына

Цифровой атлас Беларуси с 27 местами и заданиями, личным прогрессом, рейтингом, дуэлями, командными батлами, чатом, наградами и страницей идей.

## Стек технологий

- **Frontend:** статические страницы + Vite + JavaScript + CSS
- **Backend:** Go + JWT, Vercel Function для опубликованного API
- **База данных:** Turso (облачная SQLite); локально — SQLite с `modernc.org/sqlite`

## Запуск проекта

### 1. Бэкенд

```bash
npm run dev:backend
```

Бэкенд запустится на `http://127.0.0.1:8081`. Проверка состояния доступна по адресу
`http://127.0.0.1:8081/api/health` и должна вернуть `{"status":"ok"}`.

### 2. Фронтенд

В новом терминале:

```bash
npm install
npm run dev
```

Открой в браузере `http://localhost:5173`.

Vite автоматически перенаправляет запросы `/api` на локальный бэкенд. Для отдельного
развёртывания фронтенда укажи переменную сборки `VITE_API_URL` в файле
`.env.production`:

```env
VITE_API_URL=https://your-backend.example.com
```

После этого выполни `npm run build`.

Путь к SQLite можно изменить переменной `DATABASE_PATH`. Если Telegram-боты не
настроены, идеи пользователей всё равно сохраняются в таблице `suggestions`.

## Проверка

```bash
npm run lint
npm run build
npm run test:backend
npm run audit:assets
```

Сквозной тест проверяет регистрацию, авторизацию, чат, дуэли, командные игры,
сохранение идей и операции администратора.

## Данные администратора

Администратор создаётся только при настройке `ADMIN_EMAIL` и `ADMIN_PASSWORD` (минимум 6 символов; для публичного сайта рекомендуется длинный уникальный пароль). Пароль хранится в SQLite как bcrypt-хеш. Для постоянных сессий на сервере также необходимо задать `JWT_SECRET`.

## Публикация

Vercel собирает сайт командой `npm run build`. Маршрут `/api/*` вызывает
`api/handler.go`, который использует тот же Go-бэкенд из пакета `backend`.
Пользователи, статьи, вопросы, результаты, награды и игры хранятся в Turso.
Опубликованный сайт работает без локального компьютера и ngrok.

В закрытых переменных **Production** на Vercel необходимо настроить:

- `TURSO_DATABASE_URL` — адрес облачной SQLite
- `TURSO_AUTH_TOKEN` — ключ чтения и записи только этой базы
- `JWT_SECRET` — постоянный секрет длиной от 32 символов

Эти значения используются только на сервере. Нельзя добавлять к их именам
префикс `VITE_`, помещать их в HTML или коммитить в Git. Функция и база
находятся в регионе Ирландии. Создание схемы и начальные данные не выполняются
при каждом холодном запуске функции: используется заранее перенесённая база.
Изменение переменных Vercel требует новой публикации.

Перенос в **пустую** базу Turso выполняется скриптом, который делает согласованную
SQLite-копию, импортирует её и сравнивает каждую строку всех таблиц:

```bash
python scripts/migrate-turso.py --source backend/cultcode.db --credentials .private/turso.env --backup .private/spadchina-backup.db
```

Файл с ключами и резервные копии в `.private/` исключены из Git и загрузки Vercel.
Скрипт откажется перезаписывать уже заполненную базу. После переключения
облачная база является основным источником данных; локальная копия используется
для резервного восстановления и разработки.

Для отдельного локального запуска используется:

```powershell
./scripts/start-local.ps1
```

В `backend/.env` задаются `ADMIN_EMAIL`, `ADMIN_PASSWORD` и `JWT_SECRET`;
этот файл исключён из Git. Для локальной разработки без Turso достаточно
не задавать `TURSO_DATABASE_URL`. `GET /api/health` на адресе Vercel должен
вернуть `{"status":"ok"}`. Идеи сохраняются в таблице `suggestions`
даже без Telegram-бота. Фоновый Telegram polling работает только в режиме
отдельного локального сервера и не запускается в Vercel Function.

## Возможности админки

- Страница `/admin.html` открывается после входа с ролью `admin`; ссылка появляется в меню сайта
- Добавление, редактирование и удаление отдельных вопросов для дуэлей и командных баттлов
- Добавление, редактирование и удаление наград из каталога магазина
- Добавление новых статей
- Редактирование существующих статей
- Удаление статей
- Просмотр списка пользователей
- Удаление пользователей (кроме администратора)

Вопросы из админки попадают в новые баттлы; уже созданные игры сохраняют прежние вопросы. Новые награды сразу появляются в магазине. Опубликованные статьи, тексты и вопросы читаются из облачной базы и сразу появляются в публичном каталоге. Для новых материалов используется `/article.html?slug=...`; ссылки на прежние 27 мест сохраняются. На главной странице используется встроенная карта Яндекса.

В разделе «Идеи» видны сообщения, присланные через форму сайта. В разделе «Настройки» можно сменить пароль администратора, указав текущий и новый пароль (минимум 12 символов). Перезапуск локального сервера не сбрасывает пароль существующего администратора.

Задания отправляют на сервер `answers` (список `question_id` и `selected`) и `version` из `quiz_version` статьи. Сервер проверяет ответы по базе; присланные `score` и `max_score` не используются. Лучший результат сохраняется без повторного начисления баллов. Изменение вопросов во время прохождения требует перезагрузить статью. Ответы для баттлов также проверяются сервером и не включаются в выдаваемые игроку вопросы.

## API endpoints

### Публичные
- `POST /api/register` — регистрация
- `POST /api/login` — вход
- `GET /api/articles` — список статей
- `GET /api/articles/:id` — одна статья
- `GET /api/health` — состояние сервера и базы данных
- `GET /api/atlas` — опубликованные места, тексты, вопросы и координаты
- `POST /api/atlas/check` — проверка выбранного ответа для обратной связи

### Требуют авторизации
- `GET /api/me` — текущий пользователь
- `POST /api/results` — сохранить результат
- `POST /api/atlas/results` — проверить все ответы и сохранить лучший результат
- `GET /api/results/my` — мои результаты
- `GET /api/progress` — прогресс
- `GET /api/chat/conversations` — список диалогов
- `GET /api/chat/messages?peer=username` — сообщения с пользователем
- `POST /api/chat/messages` — отправить сообщение
- `GET /api/chat/unread` — количество непрочитанных сообщений

### Требуют роли admin
- `GET /api/admin/articles` — статьи вместе с правильными ответами и настройками публикации
- `GET /api/admin/suggestions` — входящие идеи
- `POST /api/admin/password` — сменить свой пароль
- `POST /api/admin/articles` — создать статью
- `PUT /api/admin/articles/:id` — обновить статью
- `DELETE /api/admin/articles/:id` — удалить статью
- `GET /api/admin/users` — список пользователей
- `DELETE /api/admin/users/:id` — удалить пользователя
- `GET/POST /api/admin/questions` — список и создание вопросов баттлов
- `PUT/DELETE /api/admin/questions/:id` — изменение и удаление вопроса
- `GET/POST /api/admin/rewards` — список и создание наград
- `PUT/DELETE /api/admin/rewards/:id` — изменение и удаление награды
